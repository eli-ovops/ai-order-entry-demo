# 04 不做范围

## 目的

本文件用于在售前、方案确认和交付启动时统一边界，避免客户把第一阶段 MVP 理解为完整业务系统、财务系统、ERP 集成项目或无人值守自动化系统。

## 明确不做范围

| 不做范围 | 说明 | 建议沟通话术 |
| --- | --- | --- |
| 不对接 ERP | 第一阶段不读取、不写入 ERP，不处理主数据同步 | MVP 先通过 Excel 交付识别结果，待价值验证后再讨论系统集成 |
| 不做财务系统 | 不建设凭证、应收应付、税务、结算、对账等财务模块 | 金额字段可识别和校验，但不承担财务核算职责 |
| 不做全链路供应链 | 不覆盖采购、库存、销售、物流、发货、收货、对账全流程 | 当前只做单据录入自动化，不改造客户业务流程 |
| 不承诺 100% 准确率 | OCR 和 LLM 都可能受图片质量、格式变化、字段歧义影响 | 系统目标是降低录入工作量，不是替代全部人工判断 |
| 不做无人审核 | AI 结果必须经过人工校验后才能保存和导出 | 第一阶段保留人工审核是控制业务风险的必要设计 |
| 不做生产级高并发 | 不针对大规模并发、复杂权限、多租户、高可用做完整建设 | MVP 优先验证业务价值和字段准确性，不做过度架构 |

## 容易混淆但不属于 MVP 的需求

| 需求 | 是否纳入 MVP | 说明 |
| --- | --- | --- |
| 自动写入 ERP | 否 | 属于系统集成，建议二期评估 |
| 自动生成财务凭证 | 否 | 属于财务系统能力 |
| 自动触发审批流 | 否 | 属于 OA 或流程引擎能力 |
| 自动匹配客户主数据 | 暂不纳入 | 第一阶段可人工校验，后续再做主数据对接 |
| 自动判断合同履约 | 否 | 超出录单 MVP 范围 |
| 多角色复杂权限 | 暂不纳入 | 第一阶段只做基础账号或简化权限 |
| 移动端完整应用 | 否 | 可支持移动上传作为后续需求，不做完整 App |
| 大屏报表 | 否 | 可保留基础统计，不做管理驾驶舱 |
| 复杂异常工单 | 否 | 第一阶段只记录失败原因，不做工单系统 |
| 模型训练平台 | 否 | 可做提示词和样本优化，不建设训练平台 |

## 可作为二期评估的方向

| 方向 | 前置条件 |
| --- | --- |
| ERP / WMS / 财务系统对接 | MVP 数据字段稳定，客户确认接口和主数据规则 |
| 客户或物料主数据匹配 | 客户提供完整主数据表和匹配规则 |
| 批量任务队列和高并发 | 客户单据量达到明确规模，并确认性能指标 |
| 复杂权限和组织架构 | 客户确认角色、部门、数据权限边界 |
| 识别准确率持续优化 | 积累足够真实样本和人工修正记录 |
| 报表和管理看板 | 客户明确管理指标和统计口径 |

## 边界确认建议

在项目启动前，建议客户书面确认：

1. 第一阶段只交付 AI 录单 MVP，不替代现有业务系统。
2. 所有 AI 识别结果必须经过人工校验。
3. Excel 导出是第一阶段的主要数据交付方式。
4. 准确率以样本测试和字段维度统计为准，不承诺所有单据 100% 正确。
5. 二期需求需要基于 MVP 结果另行评估范围、周期和费用。
